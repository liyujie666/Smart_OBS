# 第10章 错误处理与重连策略

## 10.1 错误分类

### 可恢复错误

| 错误类型 | 示例 | 处理策略 |
|----------|------|----------|
| 网络瞬断 | TCP连接断开 | 立即重连 |
| DNS解析失败 | 临时DNS故障 | 退避重连 |
| 握手超时 | 网络延迟高 | 退避重连 |
| 服务器临时错误 | 503错误 | 退避重连 |

### 不可恢复错误

| 错误类型 | 示例 | 处理策略 |
|----------|------|----------|
| 认证失败 | 密钥错误 | 停止推流，通知上层 |
| URL格式错误 | 无效URL | 停止推流，通知上层 |
| 流名冲突 | 已有同名推流 | 停止推流，通知上层 |
| 服务器拒绝 | connect被拒绝 | 停止推流，通知上层 |

## 10.2 错误检测

### 网络层错误

```cpp
bool Session::pumpRead() {
    uint8_t buffer[8192];
    int received = transport_->recv(buffer, sizeof(buffer));
    
    if (received < 0) {
        int err = transport_->getLastError();
        if (err != EWOULDBLOCK) {
            LOG_ERROR("Network error: {}", err);
            setState(SessionState::Error, "Network error");
            scheduleReconnect();
            return false;
        }
    } else if (received == 0) {
        LOG_INFO("Connection closed by peer");
        setState(SessionState::Error, "Connection closed");
        scheduleReconnect();
        return false;
    }
    
    inBuffer_.append(buffer, received);
    return true;
}
```

### 协议层错误

```cpp
void Session::onCommandMessage(const RtmpMessage& msg) {
    Amf0Decoder decoder(msg.payload);
    std::string command = decoder.decodeString();
    
    if (command == "_error") {
        Amf0Value errorInfo = decoder.decode();
        std::string code = errorInfo.getString("code");
        std::string description = errorInfo.getString("description");
        
        LOG_ERROR("Command error: code={}, desc={}", code, description);
        
        if (code == "NetConnection.Connect.Rejected" ||
            code == "NetStream.Publish.BadName") {
            // 不可恢复错误
            setState(SessionState::Error, description);
        } else {
            // 可能可恢复，尝试重连
            setState(SessionState::Error, description);
            scheduleReconnect();
        }
    }
}
```

## 10.3 指数退避重连

### 退避算法

```cpp
class ExponentialBackoff {
    int baseMs_;
    int maxMs_;
    int attempt_ = 0;
    std::mt19937 rng_;
    
public:
    ExponentialBackoff(int baseMs, int maxMs) 
        : baseMs_(baseMs), maxMs_(maxMs), rng_(std::random_device{}()) {}
    
    int nextDelay() {
        int delay = baseMs_ * (1 << attempt_);
        delay = std::min(delay, maxMs_);
        
        // 添加抖动 (±25%)，避免大量客户端同时重连
        std::uniform_int_distribution<int> dist(
            delay * 3 / 4, delay * 5 / 4);
        delay = dist(rng_);
        
        attempt_++;
        return delay;
    }
    
    void reset() { attempt_ = 0; }
};
```

**退避示例**:

```
attempt  delay (不含抖动)
0        1s
1        2s
2        4s
3        8s
4        16s
5+       30s (上限)
```

对应你的SDK配置:

```cpp
PublisherConfig config;
config.reconnectBaseMs = 1000;   // 基础延迟1秒
config.reconnectMaxMs  = 30000;  // 最大延迟30秒
```

**为什么需要抖动**: 避免大量客户端同时重连造成服务器雪崩。

## 10.4 完整重连流程

```cpp
void Session::scheduleReconnect() {
    if (!config_.autoReconnect) {
        LOG_INFO("Auto reconnect disabled");
        return;
    }
    
    cleanup();
    setState(SessionState::Backoff, "Waiting to reconnect");
    reconnectScheduler_.schedule();
}

bool Session::step(int timeoutMs) {
    if (state_ == SessionState::Backoff && 
        reconnectScheduler_.isReady()) {
        LOG_INFO("Reconnecting...");
        setState(SessionState::Reconnecting);
        start();
        return true;
    }
    return true;
}

void Session::onConnected() {
    reconnectScheduler_.reset();  // 连接成功，重置退避计数器
    setState(SessionState::Handshaking);
}
```

## 10.5 重连时的数据处理

### 关键帧等待

重连成功后，等待关键帧再发送视频数据:

```cpp
void Session::onPublishStart() {
    LOG_INFO("Publish started");
    setState(SessionState::Streaming, "Ready to stream");
    
    sendMetadata();
    sendVideoSequenceHeader();
    sendAudioSequenceHeader();
    
    waitingForKeyframe_ = true;
    requestKeyframe();
}

bool Session::sendVideoSample(const MediaSample& sample) {
    if (waitingForKeyframe_) {
        if (sample.type == SampleType::VideoKey) {
            waitingForKeyframe_ = false;
            LOG_INFO("First keyframe after reconnect");
        } else {
            return false;  // 丢弃非关键帧
        }
    }
    return sendVideoFrame(sample);
}
```

**为什么需要等待关键帧**:
- 播放器从关键帧开始才能正确解码
- 避免重连后出现花屏
- 保证流的连续性

## 10.6 健康检查与心跳

虽然RTMP没有明确的心跳协议，但可以通过Ping/Pong实现:

```cpp
class HeartbeatManager {
    std::chrono::steady_clock::time_point lastSendTime_;
    std::chrono::steady_clock::time_point lastRecvTime_;
    int intervalMs_ = 5000;   // 5秒发送一次
    int timeoutMs_ = 15000;   // 15秒无响应超时
    
public:
    bool shouldSendPing() const {
        auto elapsed = std::chrono::steady_clock::now() - lastSendTime_;
        return elapsed > std::chrono::milliseconds(intervalMs_);
    }
    
    bool isTimeout() const {
        auto elapsed = std::chrono::steady_clock::now() - lastRecvTime_;
        return elapsed > std::chrono::milliseconds(timeoutMs_);
    }
    
    void onPingSent() { lastSendTime_ = std::chrono::steady_clock::now(); }
    void onDataReceived() { lastRecvTime_ = std::chrono::steady_clock::now(); }
};

void Session::step(int timeoutMs) {
    // 检查心跳超时
    if (heartbeat_.isTimeout()) {
        LOG_ERROR("Heartbeat timeout, connection dead");
        setState(SessionState::Error, "Timeout");
        scheduleReconnect();
        return;
    }
    
    // 发送Ping
    if (state_ == SessionState::Streaming && 
        heartbeat_.shouldSendPing()) {
        sendPing();
    }
}

void Session::sendPing() {
    // User Control Message: Ping Request (type=6)
    RtmpMessage msg;
    msg.typeId = MessageType::UserControl;
    msg.csid = 2;
    
    ByteBuffer payload;
    payload.writeU16BE(6);  // Ping Request
    payload.writeU32BE(getCurrentTimeMs());
    
    msg.payload = payload.data();
    chunkWriter_.write(msg, outBuffer_);
    
    heartbeat_.onPingSent();
}
```

## 10.8 日志与调试

### 分级日志

```cpp
enum class LogLevel {
    Debug,
    Info,
    Warn,
    Error
};

class Logger {
    LogLevel level_ = LogLevel::Info;
    std::ofstream file_;
    
public:
    template<typename... Args>
    void log(LogLevel level, const char* fmt, Args&&... args) {
        if (level < level_) return;
        
        auto now = std::chrono::system_clock::now();
        auto time = std::chrono::system_clock::to_time_t(now);
        auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(
            now.time_since_epoch()) % 1000;
        
        char buffer[1024];
        snprintf(buffer, sizeof(buffer), "[%s.%03lld] [%s] ",
                 formatTime(time), ms.count(), levelToString(level));
        
        printf("%s", buffer);
        printf(fmt, std::forward<Args>(args)...);
        printf("\n");
        
        if (file_.is_open()) {
            file_ << buffer;
            // ... 写入文件
        }
    }
};

#define LOG_DEBUG(...) Logger::instance().log(LogLevel::Debug, __VA_ARGS__)
#define LOG_INFO(...)  Logger::instance().log(LogLevel::Info, __VA_ARGS__)
#define LOG_WARN(...)  Logger::instance().log(LogLevel::Warn, __VA_ARGS__)
#define LOG_ERROR(...) Logger::instance().log(LogLevel::Error, __VA_ARGS__)
```

## 本章总结

错误处理和重连是推流SDK稳定性的关键：

**核心要点**:
- 区分可恢复和不可恢复错误
- 使用指数退避算法避免服务器雪崩
- 重连后必须等待关键帧
- 通过心跳机制及时发现连接问题
- 详细的统计和日志帮助定位问题

**最佳实践**:
- 退避延迟添加随机抖动
- 重连次数和最大延迟要有上限
- 统计信息定期上报
- 日志分级，生产环境关闭Debug日志
- 关键错误要通知上层应用

通过完善的错误处理和重连机制，你的SDK可以在复杂的网络环境下稳定运行！
