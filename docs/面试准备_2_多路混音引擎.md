# 多路混音引擎 —— 面试准备文档

## 一、架构总览

```
┌──────────────────────────────────────────────────────┐
│        Audio Sources (各自独立线程采集)    │
│  DesktopAudioSource / MicrophoneAudioSource / Media   │
└────────────┬─────────────────────────────────────────┘
        │ AVFrame (各源可能不同采样率/格式)
          ▼
┌────────────────────────┐
│  FrameQueue (每源一个)  │  容量上限: 50帧
└────────────┬───────────┘
             │
    ▼
┌─────────────────────────────────────────────────────────────┐
│          AudioMixProcessor (混音处理核心)     │
│              │
│  ┌─────────────┐   ┌──────────────┐   ┌────────────────┐   │
│  │ frameCaches_ │   │ AudioMixer   │   │ OffsetManager  │   │
│  │ (每源≤5帧)   │   │ (FilterGraph)│   │ (PTS偏移补偿)  │   │
│  └──────┬──────┘   └──────┬───────┘   └────────────────┘   │
│         │   │      │
│         ▼                  ▼      │
│  帧对齐/切片 → 送入 abuffer → amix → aformat → abuffersink  │
│      │
│  速率控制 + AVSyncClock PTS赋值        │
└────────────┬────────────────────────────────────────────────┘
       │ 混音后 AVFrame (48kHz/2ch/FLTP)
       ▼
┌────────────────────┐
│  SyncCore          │  以音频帧为时间基准匹配视频帧
└────────────────────┘
```

## 二、FFmpeg Filter Graph 构建

### 拓扑结构
```
[abuffer_0] ─┐
[abuffer_1] ─┼─▶ [amix] ──▶ [aformat] ──▶ [abuffersink]
[abuffer_N] ─┘
```

### 关键参数
| 滤镜 | 参数 | 说明 |
|------|------|------|
| abuffer | `sample_rate=48000:sample_fmt=fltp:channel_layout=0x3` | 输入格式声明 |
| amix | `inputs=N:duration=longest:dropout_transition=0.1` | N路混合，最长持续，退出渐变0.1s |
| aformat | `sample_fmts=fltp:sample_rates=48000:channel_layouts=0x3` | 强制输出格式 |
| abuffersink | (无参数) | 输出端 |

### 构建 API 调用序列
```cpp
// 1. 创建图
filterGraph_ = avfilter_graph_alloc();

// 2. 创建 amix 滤镜
amix = avfilter_get_by_name("amix");
avfilter_graph_alloc_filter(filterGraph_, amix, "amix");
avfilter_init_str(mixFilterCtx_, "inputs=2:duration=longest:dropout_transition=0.1");

// 3. 创建 aformat
aformat = avfilter_get_by_name("aformat");
avfilter_graph_alloc_filter(...);
avfilter_init_str(formatCtx, "sample_fmts=fltp:sample_rates=48000:channel_layouts=0x3");

// 4. 创建 abuffersink
abuffersink = avfilter_get_by_name("abuffersink");
avfilter_graph_alloc_filter(...);
avfilter_init_str(sinkCtx, nullptr);

// 5. 循环创建每个输入源的 abuffer
for (auto& [idx, info] : inputInfos_) {
    abuffer = avfilter_get_by_name("abuffer");
    avfilter_graph_alloc_filter(...);
    avfilter_init_str(info.filterCtx, "sample_rate=48000:sample_fmt=fltp:channel_layout=0x3");
    avfilter_link(info.filterCtx, 0, mixFilterCtx_, index);  // 连接到 amix 的第 index 个 pad
}

// 6. 连接 amix → aformat → abuffersink
avfilter_link(mixFilterCtx_, 0, formatCtx, 0);
avfilter_link(formatCtx, 0, sinkCtx_, 0);

// 7. 配置整个图
avfilter_graph_config(filterGraph_, nullptr);
```

## 三、动态增减音源

### 实现方式：重建 Filter Graph

**原因**：FFmpeg 的 amix 滤镜在 `avfilter_graph_config` 后输入数量固定，不支持运行时动态增减 pad。

**流程**：
```
1. release()  → 释放旧 filterGraph
2. 更新 inputInfos_ map（增/删音源）
3. addInput() × N  → 重新注册所有活跃音源
4. init()  → 重建整个 filter graph
```

**优化**：在 `AudioFilterGraph` 实现中，维护 `nextPtsPerInput_` 数组，重建后根据已累计的 PTS 继续递增，避免时间戳跳变。

### "热插拔"的含义
- 不是真正的不停机增减，而是在混音线程的一次迭代间隙快速重建
- 重建耗时约 1-2ms（纯内存操作），对 48kHz 输出（每帧 21ms）影响极小
- 外部感知为"无缝切换"

## 四、PTS 校准算法（AVSyncClock 渐进式补偿）

### 核心问题
音频源的实际采集时间与理论 PTS 之间会产生累积偏差（如声卡时钟漂移、线程调度抖动），如果直接跳变 PTS 会导致编码器输出不均匀帧间距→播放器卡顿。

### 算法
```cpp
void AVSyncClock::calibrateAudio(int64_t elapsedUs) {
    // 1. 计算理论 PTS
    int64_t expectedPts = aFrameCount * round(aFrameDurationUs);

    // 2. 计算偏差
    int64_t drift = elapsedUs - expectedPts;

    // 3. 偏差过小则忽略（< 0.5 帧时长）
    if (abs(drift) < aFrameDurationUs / 2) return;

 // 4. 分 30+ 帧渐进补偿
    int spreadFrames = max(30, abs(drift) / aFrameDurationUs);
    aCompensatePerFrameUs = drift / spreadFrames;

    // 5. 安全约束：每帧补偿量不超过 2 倍帧时长
    aCompensatePerFrameUs = clamp(aCompensatePerFrameUs,
             -2 * aFrameDurationUs,
    +2 * aFrameDurationUs);
}

int64_t AVSyncClock::getAPts() {
    int64_t basePts = aFrameCount * round(aFrameDurationUs);
    int64_t newPts = basePts + aCompensatePerFrameUs;

    // 单调递增保证
    if (newPts <= aLastPts) newPts = aLastPts + 1;

 aLastPts = newPts;
    aFrameCount++;
    return newPts;
}
```

### 为什么是 30 帧？
- 48kHz/1024 samples = 约 21.3ms/帧
- 30 帧 ≈ 640ms，即偏差在 640ms 内平滑补完
- 太少（如 5 帧）→ 单帧补偿量大，编码器仍会感知到不均匀
- 太多（如 200 帧）→ 补偿太慢，偏差持续累积

## 五、帧缓存与速率控制

### AudioMixProcessor 驱动逻辑
```cpp
void AudioMixProcessor::processLoop() {
    while (running_) {
        // 1. 从各源 FrameQueue 拉取帧到本地缓存
  for (auto& [id, cache] : frameCaches_) {
            while (cache.size() < 5 && sourceQueue[id].tryPop(frame)) {
    cache.push_back(frame);
            }
        }

        // 2. 送入 AudioMixer
        for (auto& [id, cache] : frameCaches_) {
if (!cache.empty()) {
   audioMixer_.feedInput(id, cache.front());
         cache.pop_front();
    }
        }

        // 3. 从 sink 取出混音结果
        AVFrame* mixed = audioMixer_.getOutput();

   // 4. 速率控制
        int64_t currentUs = GlobalClock::getInstance().getCurrentUs();
        nextOutputUs += frameDurationUs;
        int64_t sleepUs = nextOutputUs - currentUs;

        // 5. 高负载处理
   int totalQueueSize = sumAllQueueSizes();
   if (totalQueueSize > HIGH_LOAD_THRESHOLD) {
            sleepUs = sleepUs * 0.5;  // 加速消费
        }

        // 6. PTS 赋值
   mixed->pts = syncClock_->getAPts();

// 7. 输出
     outputQueue_.push(mixed);

     if (sleepUs > 0) usleep(sleepUs);
    }
}
```

### 帧对齐与切片
- `alignFrameSamples()`：如果输入帧样本数 < 1024，用静音填充到 1024
- `sliceFrame()`：如果输入帧样本数 > 1024，按 1024 切片为多个小帧
- 保证送入 amix 的每帧统一为 1024 samples

## 六、OffsetManager（全局/源级偏移）

```cpp
class OffsetManager {
    int64_t globalAudioOffsetMs;    // 全局音频偏移
    int64_t globalVideoOffsetMs;    // 全局视频偏移
 map<int, int64_t> sourceOffsets; // 单源偏移

    int64_t applyOffset(int sourceId, int64_t pts) {
        int64_t offset = globalAudioOffsetMs + sourceOffsets[sourceId];
int64_t result = pts + offset * 1000;  // ms → us

        // 单调递增保证
        if (result <= lastSourcePts[sourceId]) {
        result = lastSourcePts[sourceId] + 1;
        }
        lastSourcePts[sourceId] = result;
        return result;
    }
};
```

## 七、开发中遇到的问题与解决方案

### 问题 1：动态添加音源后出现刺耳爆音

**现象**：运行中添加麦克风音源时，输出突然出现一声"噼啪"爆音。

**原因**：新音源的第一帧 PTS 为 0（从头开始），而 amix 已经在 PTS=10s 的位置。FFmpeg amix 内部会尝试对齐时间轴，导致瞬间产生巨大 PTS 跳变，编码器把多帧挤压到一个输出周期。

**解决**：
1. 重建 filter graph 时，在 `AudioFilterGraph` 中维护 `nextPtsPerInput_[sourceId]`
2. 新音源首帧 PTS 直接从当前全局时间开始赋值，而非从 0 开始
3. 送入 abuffer 前检测 PTS 跳变 > 阈值（如 100ms），自动插入静音帧填补空隙

---

### 问题 2：桌面音频和麦克风存在 50-100ms 固有延迟差

**现象**：录制中麦克风声音总是比桌面音频快约 50-100ms，用户感知为"回声"。

**原因**：
- 桌面音频（WASAPI loopback）有固有的 buffer 延迟（通常 20-50ms）
- 麦克风采集延迟较小（5-10ms）
- 两者采集路径不同，硬件 buffer 大小不同

**解决**：
1. 通过 `OffsetManager` 允许用户手动设置单源偏移补偿
2. 代码中提供默认偏移：桌面音频源 `defaultOffsetMs = -40`（提前 40ms 对齐）
3. 长期方案：利用 WASAPI 的 `IAudioClock::GetPosition` 获取精确的设备时间戳做自动校准

---

### 问题 3：长时间运行后音视频逐渐不同步

**现象**：推流 2-3 小时后，音频比视频慢约 200-500ms。

**原因**：音频帧 PTS 基于帧计数器递增 `aFrameCount * frameDuration`，但 `frameDuration` 是浮点数（如 21333.33us for 48kHz/1024），累积浮点误差导致 PTS 漂移。

**解决**：
1. 引入 `calibrateAudio()` 定期（每秒）与系统时钟对比检测偏差
2. 使用渐进式补偿而非直接跳变
3. 视频侧使用 `calibrateVideo()` 当偏差超过 50ms 时直接重置帧计数器（视频容忍突变）

---

### 问题 4：某个音源突然静音后 amix 输出也变静音

**现象**：拔掉麦克风后，整个混音输出（包括桌面音频）停止输出。

**原因**：amix 参数 `duration=longest` 意味着等待所有输入。当某个 abuffer 停止送帧，amix 会等待该输入的下一帧（认为是延迟而非结束），导致整个管线阻塞。

**解决**：
1. 对已断开的音源，定期向其 abuffer 送入静音帧保持心跳
2. 当检测到音源断开（连续 500ms 无帧），触发 filter graph 重建（移除该音源）
3. 设置 `dropout_transition=0.1` 让 amix 对缺失输入做 100ms 淡出而非阻塞等待

---

### 问题 5：音频帧切片后输出有杂音

**现象**：某些音频源送入 2048 samples 的帧，切片为 2 个 1024 帧后，第二个子帧开头有轻微杂音。

**原因**：`sliceFrame()` 中直接按字节偏移切割 `AVFrame->data[0]`，但对于 planar 格式（FLTP），每个 channel 存储在不同平面，偏移计算需要乘以 `sizeof(float)` 而非 `av_get_bytes_per_sample()`。

**解决**：
```cpp
// 正确的 planar 格式切片
for (int ch = 0; ch < channels; ch++) {
    float* src = (float*)frame->extended_data[ch];
    float* dst = (float*)slice->extended_data[ch];
    memcpy(dst, src + offset_samples, 1024 * sizeof(float));
}
```

## 八、面试必须掌握的知识点

### 1. FFmpeg Filter Graph 基本概念
- **AVFilterGraph**：滤镜图容器
- **AVFilterContext**：滤镜实例（带参数的滤镜节点）
- **avfilter_link**：连接两个滤镜的 output pad 和 input pad
- **av_buffersrc_add_frame**：向 abuffer 送入帧
- **av_buffersink_get_frame**：从 abuffersink 取出帧

### 2. amix 滤镜的行为
- 多路输入等时对齐后逐样本相加
- `duration=longest`：以最长输入为准，短输入结束后填零
- `dropout_transition`：输入退出时的淡出时间
- 输出样本值 = 各输入对应样本的加权和（默认等权 1/N）

### 3. 音频采样格式
| 格式 | 说明 |
|------|------|
| AV_SAMPLE_FMT_S16 | 16位整数，交错存储 |
| AV_SAMPLE_FMT_FLT | 32位浮点，交错存储 |
| AV_SAMPLE_FMT_FLTP | 32位浮点，planar 存储（每通道独立数组） |

- **交错(Interleaved)**：LRLRLR...（data[0] 包含所有通道）
- **平面(Planar)**：LLL.../RRR...（data[0]=左声道, data[1]=右声道）

### 4. PTS 与时间基
- PTS = Presentation Time Stamp，单位由 time_base 决定
- 音频常用 time_base = 1/sample_rate（如 1/48000）
- 1024 samples @ 48kHz = 1024/48000 s ≈ 21.33ms

### 5. 为什么选 FFmpeg filter graph 而非手动混音？
- FFmpeg 内部做了采样率转换、格式对齐、通道映射
- amix 内部有精确的时间戳对齐逻辑
- 一套代码适配任意输入格式组合
- 如果手动实现需要自己处理重采样 + 格式转换 + 时间对齐

### 6. 渐进式 PTS 补偿 vs 直接跳变
| 方案 | 优点 | 缺点 |
|------|------|------|
| 直接跳变 | 实现简单，一步到位 | 编码器输出帧间距突变，播放器可能卡顿 |
| 渐进式补偿 | 帧间距平滑过渡，编码器输出稳定 | 补偿速度慢，极端偏差需要更长时间收敛 |

### 7. 对象池（GlobalPool）
- `getFramePool()`：复用 AVFrame，避免高频 `av_frame_alloc/free`
- 48kHz/1024 samples → 每秒约 47 帧，不用池会造成大量 malloc/free 开销
